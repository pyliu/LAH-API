文件版本：v1.1（2026-10-23）

第一章：整體升級策略與系統架構藍圖

1.1 核心設計決策

  1. 新舊目錄並存（www/ 與 v85/）：既有 LAH-API/www/ 維持 PHP 7.3/7.4 穩定運作；新建 LAH-API/API/ 作為 PHP 8.5 專屬目錄，逐支檢視、修正並遷移 API。
  2. 保留 Apache 2.4 並啟用 mod_proxy_fcgi 分流：不替換現有 Apache 2.4 服務，各所防火牆與自動更新工具 LAH-Updater 無需大幅變動。Apache 以原本的 mod_php7 服務 /，同時將 /v85/ 轉發給本機 Port 9085 的 PHP 8.5 FastCGI。
  3. PM2 進程守護與 FastCGI 原生多程序併發：利用各所伺服器既有的 PM2 守護 C:\AppServ\php85\php-cgi.exe（設定 exec_mode: "fork"），並藉由 FastCGI 內部環境變數 PHP_FCGI_CHILDREN: "16" 由 Windows 核心自動衍生 16 個 Worker 程序，徹底解決 Windows 下 FastCGI 請求併發與崩潰重啟問題。

第二章：Node.js v16 限制、PM2 託管與 C:\AppServ\node 隔離架構

2.1 關鍵解答：PM2 託管 PHP 8.5 完全不受 Node.js v16 限制！

  • 為什麼不需要升級 Node.js 或切換 NVM 就能用 PM2 管 PHP 8.5？
    PM2 雖然執行於 Node.js v16 上，但當設定 interpreter: "none" 時，PM2 是直接透過 Windows 系統呼叫啟動原生的 C:\AppServ\php85\php-cgi.exe 執行檔，並監控其 PID。因此，現有跑在 Node.js v16 上的 PM2 可以直接同時管理 LAH-FE (Node 16)、lah-messenger-server 與 lah-api-v85 (PHP 8.5)，完全不會互相干擾！

2.2 進階避坑與架構設計：LAH-FE 的 Cluster 限制與 C:\AppServ\node 專屬隔離

💡 核心觀念：PM2 cluster 模式下的 interpreter 繼承原理
工程師常直覺想在 LAH-FE 的 ecosystem.config.js 中指定 interpreter: "C:/AppServ/node/node.exe" 來鎖定 Node 16。然而在 PM2 的底層架構中：
  • exec_mode: "cluster"（多行程負載均衡）：Node.js 核心的 cluster.fork() 深度依賴 PM2 Daemon 所在的執行緒，在 cluster 模式下 PM2 會忽略自訂 interpreter 路徑，強制繼承啟動 PM2 Daemon 本身的 Node 版本！
  • exec_mode: "fork"（單行程分支模式）：自訂 interpreter 才能生效，但會失去 PM2 內建的 Cluster 多核負載均衡與零停機熱重載優勢。
⚠️ Windows 上全域升級或 nvm-windows 的潛在風險：
nvm use <version> 在 Windows 的原理是動態切換全域符號連結 C:\Program Files\nodejs。若管理師日後在伺服器全域安裝或切換至 Node 20/22，當 PM2 守護服務重啟時，PM2 Daemon 便會誤以 Node 20/22 啟動，進而導致以 cluster 模式運行的 LAH-FE (Nuxt 2 / Vue 2) 因 Webpack 4 與原生模組 ABI 不相容而崩潰！

🎯 官方最佳實踐（實體專屬隔離方案）：將 Node 16.20.2 集中部署至 C:\AppServ\node\

  1. 集中放置綠色執行檔： 下載 Node.js 官方最終版本 node-v16.20.2-win-x64.zip 解壓至 C:\AppServ\node\（內含 node.exe、npm、yarn、pm2）。
  2. 鎖定 PM2 守護服務啟動源： 在 Windows 服務或 PM2 啟動腳本中，明確由 C:\AppServ\node\node.exe 來喚醒 PM2 Daemon（例如 "C:\AppServ\node\node.exe" "C:\AppServ\node\node_modules\pm2\bin\pm2" resurrect）。
  3. 徹底免疫全域環境變更： 如此一來，PM2 Daemon 本身永遠 100% 固定跑在 Node 16.20.2 上，底下的 LAH-FE（Nuxt 2）與 lah-messenger-server 在 cluster 模式下自然繼承穩定的 Node 16 執行期。無論整台伺服器全域安裝了什麼軟體或如何切換 NVM，地政智慧管控系統皆能永久穩定運行！

2.3 PM2 FastCGI 服務設定檔（C:\AppServ\LAH-API\ecosystem.config.js）

以下為專案標準 ecosystem.config.js 配置：

module.exports = {
  apps: [
    {
      name: "lah-api-v85",
      script: "C:/AppServ/php85/php-cgi.exe",
      args: "-b 127.0.0.1:9085",
      instances: 1,

      autorestart: true,

      restart_delay: 2000,

        PATH: "C:/AppServ/php85;C:/AppServ/php7;C:/Tools/instantclient_11_2;" + process.env.PATH
      }
    }
  ]
};

第三章：破解「PHP 8.5 ↔ Oracle 9i」雙重死結的實戰方案

3.1 為什麼 PHP 8.5 連 Oracle 9i 會有雙重死結？

  1. 死結 1（Client 版本限制）：Oracle Instant Client 12c / 19c 已在底層移除對 Oracle 9i (9.2) 的連線支援，連線必噴 ORA-03134: Connections to this server version are no longer supported。因此唯一能連上 Oracle 9i 的 Client 只有 instantclient_11_2 (11.2.0.4)。
  2. 死結 2（PHP 8.5 DLL 函式限制）：PHP 8.5 官方預編譯僅提供 php_oci8_12c.dll / 19.dll，其二進位匯入表強制要求 Oracle 12c 才新增的 OCIStmtGetNextResult 函式，因此無法載入 instantclient_11_2\oci.dll。

3.2 現行採用方案：智慧雙模（本機 PHP 7.4 CLI Worker 內部橋接）

由於整個專案對 Oracle 9i 的呼叫 100% 封裝於 API/include/OraDB.class.php 單一類別內，本系統已實作並全面採用本機 PHP 7.4 CLI Worker 智慧雙模內部橋接機制：

⭐ 核心優勢與採用理由：
  • 零編譯成本、立即可用：無需在 Windows 伺服器建置 Visual Studio C++ 工具鏈重新編譯非官方 DLL。
  • 業務 API 100% 零修改：現行 30 多支業務 API 的 SQL 語法與 :bv_... 具名參數綁定完全相容保留。
  • 程序隔離與安全穩定：PHP 8.5 FastCGI 程序與 PHP 7.4 CLI 獨立隔離，Oracle 9i 查詢透過標準輸入/輸出 (STDIN/STDOUT) 傳遞資料，避免記憶體洩漏互相干擾。

運作架構與資料流：

  1. 在 API/include/OraDB.class.php 建構子中自動偵測執行環境： 
    $this->use_cli_bridge = !extension_loaded('oci8');
  2. 現階段（後端為 Oracle 9i）：
    • 因 PHP 8.5 官方未提供支援 Oracle 9i 的 php_oci8_11g.dll，因此 extension_loaded('oci8') 為 false，$this->use_cli_bridge 自動判定為 true。
    • 當業務 API 呼叫 $db->execute() 時，OraDB 透過 proc_open 呼叫 C:\AppServ\php7\php.exe 執行同目錄下的 API/include/ora_cli_worker.php。
    • 該 Worker 搭配舊軌穩定運作的 instantclient_11_2 與 php_oci8_11g.dll 連線 Oracle 9i 執行查詢，並將原始 BIG5 欄位以 Base64 編碼透過 STDOUT 回傳。
    • OraDB 接收後自動調用 UConverter::transcode 轉為 UTF-8，達成 100% 正確的中文編碼轉換。

3.3 📌 未來升級備忘：資料庫升級至 Oracle 12c 時之原生 PHP 8.5 OCI8 直連無縫切換步驟

🔔 給未來的提醒（當後端資料庫從 Oracle 9i 正式升級為 Oracle 12c / 19c 時請執行此步驟）：
將來後端資料庫升級為 Oracle 12c 或更高版本 後，3.1 節所述的「雙重死結」將徹底消失！屆時不必再透過 PHP 7.4 CLI 橋接，而是可以直接啟用 純 PHP 8.5 官方原生 OCI8 高速直連。

切換為「純 PHP 8.5 官方原生直連」的 3 個操作步驟（零程式碼修改）：

  1. 更換伺服器 Instant Client 為 19c：
    • Oracle 官方規範（Doc ID 207303.1）明訂 Oracle Instant Client 19c 完全向下相容連線 Oracle 12c (12.1 / 12.2) 資料庫。
    • 請將伺服器上的 Instant Client 升級為 19c（例如解壓至 C:\AppServ\instantclient_19_25），並同步更新 API/ecosystem.config.js 中的 PATH 環境變數。
  2. 放入 PHP 8.5 官方 php_oci8_19.dll 並啟用設定：
    • 前往 PECL 官方下載頁面取得 php_oci8-3.4.1-8.5-nts-vs17-x64.zip，將裡面的 php_oci8_19.dll 複製到 C:\AppServ\php85\ext\。
    • 編輯 C:\AppServ\php85\php.ini，加入或取消註解：extension=oci8_19。
  3. 重啟 PM2 服務即自動完成切換：
    • 執行 pm2 restart lah-api-v85 --update-env。
    • 開啟 http://127.0.0.1/LAH-API/ver.php 確認 "oci8": true。
    • 一旦 extension_loaded('oci8') 為 true，API/include/OraDB.class.php 的 $this->use_cli_bridge 會自動變為 false，一行 PHP 程式碼都不用改，系統就會自動跳過 PHP 7.4 橋接，全面改走純 PHP 8.5 原生 oci_connect()、oci_parse() 與 oci_bind_by_name() 高速直連 Oracle 12c，屆時即可正式退役移除舊版 PHP 7.4！

第六章：Apache 2.4 (httpd.conf) mod_proxy_fcgi 雙軌設定

1. 於 httpd.conf 取消註解啟用模組：

LoadModule proxy_module modules/mod_proxy.so
LoadModule proxy_fcgi_module modules/mod_proxy_fcgi.so
LoadModule rewrite_module modules/mod_rewrite.so

2. 於 httpd.conf 最下方加入 /v85 路由轉發區塊：

# 優先相容舊呼叫端
Alias /LAH-API/api "C:/AppServ/LAH-API/v1"
Alias /lah-api/api "C:/AppServ/LAH-API/v1"

# 服務根目錄映射
Alias /LAH-API "C:/AppServ/LAH-API"
Alias /lah-api "C:/AppServ/LAH-API"

<Directory "C:/AppServ/LAH-API">
    Header set Access-Control-Allow-Origin "*"
    Options Indexes FollowSymLinks
    AllowOverride None
    Require all granted

    <FilesMatch "\.php$">
        <If "-f %{REQUEST_FILENAME}">
            # Windows 下結尾務必帶斜線 /，並以 ProxyFCGISetEnvIf 剝除 proxy:fcgi:// 前綴供 php-cgi.exe 讀取
            SetHandler "proxy:fcgi://127.0.0.1:9085/"
            ProxyFCGISetEnvIf "reqenv('SCRIPT_FILENAME') =~ m#^proxy:fcgi://127\.0\.0\.1:9085/(.*)$#" SCRIPT_FILENAME "$1"
        </If>
    </FilesMatch>
</Directory>

<Proxy "fcgi://127.0.0.1:9085/" enablereuse=on max=16>
    ProxySet timeout=300
</Proxy>

  1. 安裝 PHP 8.5 NTS：下載 Windows PHP 8.5 (VS17 x64 Non Thread Safe) 解壓至 C:\AppServ\php85，複製 php.ini-development 為 php.ini，開啟 curl, fileinfo, gd, intl, mbstring, odbc, openssl, pdo_odbc, pdo_sqlite, sqlite3, sockets, zip。
