第一章：整體升級策略與系統架構藍圖

1.1 核心設計決策

  1. 新舊目錄並存（www/ 與 v85/）：既有 LAH-API/www/ 維持 PHP 7.3/7.4 穩定運作；新建 LAH-API/v85/ 作為 PHP 8.5 專屬目錄，逐支檢視、修正並遷移 API。
  2. 保留 Apache 2.4 並啟用 mod_proxy_fcgi 分流：不替換現有 Apache 2.4 服務，各所防火牆與自動更新工具 LAH-Updater 無需大幅變動。Apache 以原本的 mod_php7 服務 /，同時將 /v85/ 轉發給本機 Port 9085 的 PHP 8.5 FastCGI。
  3. PM2 進程守護：利用各所伺服器既有的 PM2 守護 C:\AppServ\php85\php-cgi.exe，自動處理程序回收與崩潰重啟，徹底消除 Windows 下 FastCGI 滿載退出的 502 問題。
客戶端請求LAH-FE (Nuxt 2) / lah-messenger

第二章：Node.js v16 限制、PM2 託管與 nvm-windows 完整解析

2.1 關鍵解答：PM2 託管 PHP 8.5 完全不受 Node.js v16 限制！

  • 為什麼不需要升級 Node.js 或切換 NVM 就能用 PM2 管 PHP 8.5？
    PM2 雖然執行於 Node.js v16 上，但當設定 interpreter: "none" 時，PM2 是直接透過 Windows 系統呼叫啟動原生的 C:\AppServ\php85\php-cgi.exe 執行檔，並監控其 PID。因此，現有跑在 Node.js v16 上的 PM2 可以直接同時管理 LAH-FE (Node 16)、lah-messenger-server 與 lah-api-v85 (PHP 8.5)，完全不會互相干擾！

2.2 進階：若未來同台伺服器需安裝 nvm-windows 跑多版本 Node.js 的避坑指南

⚠️ Windows 上使用 nvm-windows 的重要陷阱：
nvm use <version> 在 Windows 的原理是切換全域符號連結 C:\Program Files\nodejs。若在伺服器上直接執行 nvm use 22，當 LAH-FE 重啟時會誤抓到 Node 22 而崩潰！
✅ 正確做法：只用 nvm install 下載各版本，並在 PM2 的 ecosystem.config.js 中以 interpreter 明確指定該版本 node.exe 的實體絕對路徑（例如 C:\nvm\v16.20.2\node.exe）。

2.3 LAH-API\v85\ecosystem.config.js 完整設定檔範本

module.exports = {
  apps: [
    {
      name: "lah-api-v85",
      script: "C:\\AppServ\\php85\\php-cgi.exe",
      args: "-b 127.0.0.1:9085 -c C:\\AppServ\\php85\\php.ini",
      cwd: __dirname,               // 自動取得目錄（各所伺服器與開發筆電 Junction 皆為 C:\\AppServ\\v85）,
      interpreter: "none",          // 告知 PM2 此為原生 Windows 執行檔，不經由 node 執行
      exec_mode: "fork",
      instances: 1,
      autorestart: true,            // 異常退出或達到 MAX_REQUESTS 時立即自動重啟
      watch: false,
      max_memory_restart: "1G",
      env: {
        PATH: "C:\\Tools\\instantclient_11_2;C:\\AppServ\\php85;" + process.env.PATH,
        NLS_LANG: "American_America.US7ASCII",
        PHP_FCGI_CHILDREN: "16",
        PHP_FCGI_MAX_REQUESTS: "10000"
      }
    }
  ]
};

第三章：破解「PHP 8.5 ↔ Oracle 9i」雙重死結的實戰方案

3.1 為什麼 PHP 8.5 連 Oracle 9i 會有雙重死結？

  1. 死結 1（Client 版本限制）：Oracle Instant Client 12c / 19c 已在底層移除對 Oracle 9i (9.2) 的連線支援，連線必噴 ORA-03134: Connections to this server version are no longer supported。因此唯一能連上 Oracle 9i 的 Client 只有 instantclient_11_2 (11.2.0.4)。
  2. 死結 2（PHP 8.5 DLL 函式限制）：PHP 8.5 官方預編譯僅提供 php_oci8_12c.dll / 19.dll，其二進位匯入表強制要求 Oracle 12c 才新增的 OCIStmtGetNextResult 函式，因此無法載入 instantclient_11_2\oci.dll。

3.2 破解方案比較（推薦在 v85/include/OraDB.class.php 採用智慧雙模）

由於整個專案對 Oracle 9i 的呼叫 100% 集中在 OraDB.class.php 單一類別內，您有以下三種選擇：

方案名稱 運作機制 建置成本與評價
🥇 方案 1（最推薦起步）：
本機 127.0.0.1 內部橋接		 雙軌期間 Apache 本來就帶有 mod_php7 + instantclient_11_2。當 v85 (PHP 8.5) 需要查 Oracle 9i 時，由 v85/include/OraDB.class.php 透過本機 127.0.0.1 內部端點委派 PHP 7 執行 SQL 並回傳結果。 ⭐ 零編譯成本、立即可用。
30 支業務 API 的 SQL 與 :bv_ 綁定一行都不用改！
🥈 方案 2（純 PHP 8.5）：
Windows ODBC 橋接		 安裝 instantclient-odbc-11.2.0.4，在 PHP 8.5 開啟內建 extension=odbc，透過 Windows odbc32.dll 呼叫 11.2 Driver 連 Oracle 9i。 ⭐⭐ 免編譯 C++，可完全移除 PHP 7；僅需改寫 OraDB.class.php 將 :var 轉為 ?。
🥉 方案 3（純 PHP 8.5 原生）：
VS2022 自編譯 DLL		 下載 PECL oci8-3.4.x 原始碼，使用 Visual Studio 2022 搭配 instantclient_11_2\sdk 自行編譯出 PHP 8.5 專用的 php_oci8_11g.dll。 ⭐⭐⭐⭐ 需建置 C++ 編譯環境，但編出後可 100% 原生呼叫 oci_connect()。

3.3 📌 給未來的備忘錄：目前 OraDB.class.php 實作狀態與將來升級 Oracle 12c 的無縫切換步驟

🔔 給未來的提醒（當後端資料庫從 Oracle 9i 正式升級為 Oracle 12c 時請執行此步驟）：
將來後端資料庫升級為 Oracle 12c 後，3.1 節所述的「雙重死結」將徹底消失！屆時完全不需要使用方案 2（Windows ODBC 橋接），也不必再透過 PHP 7.4 橋接，而是可以直接啟用 純 PHP 8.5 官方原生 OCI8 直連。

1. 目前已實作於 v85/include/OraDB.class.php 的「智慧雙模（Dual-Mode）」機制：

  • 在 v85/include/OraDB.class.php 的建構子（第 81 行）中已預先寫入自動偵測邏輯： 
    $this->use_cli_bridge = !extension_loaded('oci8');
  • 現階段（後端為 Oracle 9i）：PHP 8.5 的 php.ini 未開啟 oci8，因此 $this->use_cli_bridge 為 true。當呼叫 $db->execute() 時，會自動走方案 1（本機 PHP 7.4 內部橋接），透過 proc_open 呼叫 C:\AppServ\php7\php.exe 執行同目錄下的 v85/include/ora_cli_worker.php（搭配 instantclient_11_2 與 php_oci8_11g.dll），並將原始 BIG5 位元組以 Base64 傳回 PHP 8.5 進行轉碼。既有 30 多支業務 API 的 :bv_... 具名參數綁定一行都不用改。

2. 將來後端升級為 Oracle 12c 時，切換為「純 PHP 8.5 原生直連」的 3 個操作步驟（零程式碼修改）：

  1. 更換伺服器 Instant Client 為 19c：Oracle 官方規範（Doc ID 207303.1）明訂 Oracle Instant Client 19c 完全向下相容連線 Oracle 12c (12.1 / 12.2) 資料庫。請將伺服器上的 Instant Client 升級為 19c（例如解壓至 C:\Tools\instantclient_19_25），並同步更新 v85/ecosystem.config.js 中的 PATH 環境變數。
  2. 放入 PHP 8.5 官方 php_oci8_19.dll 並啟用設定：
    • 前往 PECL 官方下載頁面取得 php_oci8-3.4.1-8.5-nts-vs17-x64.zip，將裡面的 php_oci8_19.dll 複製到 C:\AppServ\php85\ext\。
    • 編輯 C:\AppServ\php85\php.ini，加入或取消註解：extension=oci8_19。
  3. 重啟 PM2 服務即自動完成切換：
    • 執行 pm2 restart lah-api-v85 --update-env。
    • 開啟 http://127.0.0.1/v85/ver.php 確認 "oci8": true。
    • 一旦 extension_loaded('oci8') 為 true，v85/include/OraDB.class.php 的 $this->use_cli_bridge 會自動變為 false，一行 PHP 程式碼都不用改，系統就會自動跳過 PHP 7.4 橋接，全面改走純 PHP 8.5 原生 oci_connect()、oci_parse() 與 oci_bind_by_name() 高速直連 Oracle 12c，屆時即可正式退役移除舊版 PHP 7.4！

第六章：Apache 2.4 (httpd.conf) mod_proxy_fcgi 雙軌設定

1. 於 httpd.conf 取消註解啟用模組：

LoadModule proxy_module modules/mod_proxy.so
LoadModule proxy_fcgi_module modules/mod_proxy_fcgi.so
LoadModule rewrite_module modules/mod_rewrite.so

2. 於 httpd.conf 最下方加入 /v85 路由轉發區塊：

Alias /v85 "C:/AppServ/v85"

<Directory "C:/AppServ/v85">
    Header set Access-Control-Allow-Origin "*"
    Options Indexes FollowSymLinks
    AllowOverride None
    Require all granted

    <FilesMatch "\.php$">
        <If "-f %{REQUEST_FILENAME}">
            # Windows 下結尾務必帶斜線 /，並以 ProxyFCGISetEnvIf 剝除 proxy:fcgi:// 前綴供 php-cgi.exe 讀取
            SetHandler "proxy:fcgi://127.0.0.1:9085/"
            ProxyFCGISetEnvIf "reqenv('SCRIPT_FILENAME') =~ m#^proxy:fcgi://127\.0\.0\.1:9085/(.*)$#" SCRIPT_FILENAME "$1"
        </If>
    </FilesMatch>
</Directory>

<Proxy "fcgi://127.0.0.1:9085/" enablereuse=on max=16>
    ProxySet timeout=300
</Proxy>

第七章：開發筆電（c:\Temp\DEV\LAH-Workspace）實驗步驟

  1. 安裝 PHP 8.5 NTS：下載 Windows PHP 8.5 (VS17 x64 Non Thread Safe) 解壓至 C:\AppServ\php85，複製 php.ini-development 為 php.ini，開啟 curl, fileinfo, gd, intl, mbstring, odbc, openssl, pdo_odbc, pdo_sqlite, sqlite3, sockets, zip。
  2. 建立 LAH-API\v85 目錄：將 LAH-API\v1 重新命名為 LAH-API\v85，放入 ecosystem.config.js 與測試用 ver.php。
  3. 使用 PM2 啟動 PHP 8.5 FastCGI： 
    cd C:\AppServ\v85
pm2 start ecosystem.config.js
pm2 status
  4. 驗證雙軌連線：
    • 若已啟動 Apache 2.4：瀏覽器開啟 http://127.0.0.1/ver.php (顯示 PHP 7.4) 與 http://127.0.0.1/v85/ver.php (顯示 PHP 8.5 cgi-fcgi)。
    • 若筆電未開 Apache，想快速單獨測 PHP 8.5：執行 C:\AppServ\php85\php.exe -S 127.0.0.1:8085 -t c:\Temp\DEV\LAH-Workspace\LAH-API\v85，開啟 http://127.0.0.1:8085/ver.php。
