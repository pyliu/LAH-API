壹、前言與監控架構簡介

為即時掌握各地政事務所 Oracle 資料庫（主要資料庫、所端備份庫及副中心備援庫）之 DataGuard 同步運作狀態，智慧管控系統（LAH）建置有「資料庫 Data Guard 監控看板」。

各地政事務所（中壢 hb、大溪 hc、楊梅 hd、蘆竹 he、八德 hf、平鎮 hg、龜山 hh 等）之 IBM AIX 6.1 主機，需於 root 的排程管理程式（crontab）中設定定時檢查作業，透過 oracle 帳號環境執行檢查腳本，將資料庫 Log Sequence、Switchover 狀態及主機空間等資訊自動發送通知郵件，供管控系統彙整分析並即時警示。

圖一：智慧控管系統 (LAH-FE) 監控看板說明視窗
📌 監控運作週期說明
  • 排程檢查頻率：每週一至週六，每日上午 08:00 至下午 17:00，整點執行一次（共 10 次）。
  • 儀表板更新頻率：管控系統前端每小時自動擷取最新郵件進行解析，更新同步狀態燈號。

貳、必要檔案清單與前置作業

請各所管理師先確認已自局端取得下列兩項核心腳本檔案，並放置於 oracle 家目錄下：

檔案名稱 建議存放路徑 主要功能說明
check-dataguard.sh /home/oracle/ha/ 或 /home/oracle/<所代號>/ 主執行 Shell 腳本。負責收集系統磁碟空間、錯誤報告、執行 SQL 檢查、寄發狀態郵件，並自動清除超過 7 天之歷史日誌。
check-dataguard.sql 需與上述 .sh 放置在同一工作目錄 查詢資料庫狀態 SQL 腳本。執行 archive log list、查詢 v$database 及 v$archive_gap。

步驟一：建立工作目錄與記錄檔資料夾

以 oracle 身分（或使用 root 建立後變更擁有者）在主機上建立工作目錄與 log 目錄：

# 切換至 oracle 帳號
su - oracle

# 建立工作目錄（以各所代碼為例，例如中壢所 hb）
mkdir -p /home/oracle/hb/log

# 確認目錄權限為 oracle:dba
ls -ld /home/oracle/hb /home/oracle/hb/log

步驟二：上傳腳本並賦予執行權限

將 check-dataguard.sh 與 check-dataguard.sql 上傳至該工作目錄，並設定正確執行權限：

cd /home/oracle/hb
chmod 755 check-dataguard.sh
chmod 644 check-dataguard.sql
⚠️ AIX 6.1 換行字元相容性特別提醒
若腳本檔案曾於 Windows 電腦編輯過，上傳至 AIX 執行時可能因 DOS 換行字元（CRLF）導致 ^M: not found 語法錯誤。請務必在 AIX 執行下列指令清理換行符號： 
tr -d '\r' < check-dataguard.sh > check-dataguard.sh.tmp && mv check-dataguard.sh.tmp check-dataguard.sh
chmod 755 check-dataguard.sh

參、各所參數設定與檢查清單 (Checklist)

開啟 check-dataguard.sh，請依據所屬事務所環境，修改腳本頂部的組態變數區塊：

# ------------------------------------------------------------------------------
# 伺服器識別設定（供系統管理師依部署主機設定）
# 可選值: P8-2、P7-102、hb-114
# （注意：此字串與前端 LAH-FE DataGuard 監控看板主旨連動，請勿修改為其他字串）
# ------------------------------------------------------------------------------
SERVER_ID="${1:-P8-2}"

# 相關工作目錄與檔案設定
BASE_DIR="/home/oracle/ha"
LOG_DIR="${BASE_DIR}/log"
SQL_FILE="${BASE_DIR}/check-dataguard.sql"

# 監控通報收件人信箱
MAIL_TO="hamonitor@mail.ha.cenweb.land.moi"

變數設定對照說明表

變數名稱 建議設定範例 重要注意事項
SERVER_ID P8-2 或 P7-102 或 hb-114 極重要！前端監控看板固定比對這三個關鍵字串，請務必依伺服器角色填入對應代號，切勿自訂任意字串。
BASE_DIR /home/oracle/hb 腳本與 SQL 存放之絕對路徑。若各所習慣放置於 /home/oracle/ha 亦可維持不變。
LOG_DIR ${BASE_DIR}/log 日誌存放路徑，通常直接使用 ${BASE_DIR}/log 即可。
SQL_FILE ${BASE_DIR}/check-dataguard.sql SQL 腳本完整檔案路徑。
MAIL_TO hamonitor@mail.ha.cenweb.land.moi 通報電子郵件。依各所實際監控通報信箱進行設定。
🚨 伺服器識別代號規範提醒
智慧管控前端會依據郵件主旨中的代號識別角色：
  • P8-2：對應「主要資料庫（局端 P8-2）」
  • P7-102：對應「備份資料庫（所端 P7-102）」
  • hb-114：對應「備援資料庫（副中心 HB-114）」
若填寫其他自訂字串，前端將無法判讀 Switchover 狀態與 Log Sequence 差距。

肆、Root Crontab 排程設定程序

在 IBM AIX 6.1 環境中，必須登入為 root 超級使用者來編輯排程清單。

為何必須使用 su - oracle -c？

💡 AIX 系統環境變數深度解析

Oracle 資料庫工具（如 sqlplus）的執行極度依賴帳號環境變數（包含 ORACLE_HOME、ORACLE_SID、PATH、LIBPATH 等）。

若直接在 root 的 crontab 中執行 /home/oracle/check-dataguard.sh，因缺少上述 Oracle 環境變數，會導致 sqlplus: not found 或 ORA-12154 連線失敗。透過 su - oracle -c "指令"，指令列中特別帶入的 - 參數會強制系統完整載入 oracle 帳號的 Login Profile，確保環境變數完整到位。

排程設定操作步驟

  1. 以 root 帳號登入 AIX 6.1 主機。
  2. 執行 crontab 編輯指令：crontab -e
  3. 於排程檔案末端加入下列設定行（請依實際腳本路徑調整）： 
    #ha dataguard monitor
0 8-17 * * 1-6 su - oracle -c /home/oracle/ha/check-dataguard.sh > /dev/null
  4. 儲存並退出編輯器（在 vi 中按 Esc 接著輸入 :wq）。
  5. 確認排程已正確生效：crontab -l | grep check-dataguard

伍、手動測試與驗證程序

排程設定完畢後，管理師應立即進行完整手動驗證，確認日誌生成、郵件遞送及清理功能均正常。

步驟一：模擬排程手動執行

以 root 執行與 crontab 完全相同的指令，檢視終端有無錯誤訊息：

su - oracle -c /home/oracle/ha/check-dataguard.sh

步驟二：檢查日誌內容

檢查 log 目錄是否產生最新日誌檔，並確認內容包含磁碟狀態與 SQL 查詢結果：

ls -lt /home/oracle/ha/log/
tail -n 30 /home/oracle/ha/log/check-*.log

日誌內應呈現：

  • date、df -g 及 errpt 系統資訊。
  • SQL 輸出：Database log mode: Archive Mode、Current log sequence、SWITCHOVER_STATUS: NOT ALLOWED / ACTIVE 等字樣。

步驟三：確認 7 天過期日誌自動清理機制

本腳本於末尾內建相容 AIX 6.1 POSIX 語法之歷史日誌清理指令：

find "${LOG_DIR}" -type f -name "check-*.log" -mtime +7 -exec rm -f {} \;

此指令會自動搜尋 LOG_DIR 下超過 7 天（即最後修改時間大於 7 天前）的 check-*.log 檔案並安全移除，無需手動建立維護排程。

步驟四：檢查監控信箱接收狀況

檢查收件信箱（hamonitor@... 或各所信箱）是否成功收到郵件：

  • 郵件主旨格式應為：P8-2 DataGuard STATE（或 P7-102 DataGuard STATE、hb-114 DataGuard STATE）。
  • 開啟智慧管控系統（LAH-FE）之 DataGuard 儀表板，確認對應主機是否呈現綠色正常狀態。

陸、常見問題與障礙排除 (FAQ)

Q1：收不到通知信，或日誌提示 mail: not found？

解答：請以 oracle 帳號執行 which mail 確認 AIX 郵件指令路徑（通常為 /usr/bin/mail）。若主機未開啟 sendmail 服務，郵件將無法對外遞送，請洽主機維運人員確認 AIX sendmail 常駐行程是否運作。

Q2：日誌中出現 ORA-01034: ORACLE not available 或 sqlplus: not found？

解答：此狀況通常是因為在 crontab 中未帶 - 參數（例如誤寫為 su oracle -c ...）。請務必確認為 su - oracle -c ...，確保完整載入 .profile 中的 ORACLE_HOME 及 ORACLE_SID。

Q3：在 AIX 執行時出現 find: 0465-010 Parameter -delete is not valid？

解答：AIX 6.1 的 find 工具不支援 Linux GNU 的 -delete 參數。本版本腳本已改用標準 POSIX 語法 -exec rm -f {} \;，請確認主機上使用的為最新版 check-dataguard.sh 腳本。

Q4：腳本執行出現 ^M: not found 或奇怪的語法錯誤？

解答：此為 Windows CRLF 換行字元所致。請在 AIX 伺服器終端執行 dos2unix check-dataguard.sh 或 tr -d '\r' < check-dataguard.sh > tmp.sh && mv tmp.sh check-dataguard.sh 轉為純 Unix LF 換行。
