互動式部署流程

提供清晰的建置步驟。點擊左側流程節點，即可閱讀對應操作指令與踩坑注意事項。

步驟一：前置作業與資源清理

必須關閉 Ollama 服務避免 GB10 記憶體衝突，防止模型被退回 ARM CPU 慢速運算。

sudo systemctl stop ollama
sudo systemctl disable ollama
sudo killall -9 ollama python3 2>/dev/null
free -h # 確保 Free Memory 高於 60GB
docker rm -f vllm-gemma-4 vllm-gemma4-26b 2>/dev/null

步驟二：下載模型權重

使用 hf 下載 NVFP4 量化權重（約 16.5 GB）。處理 PEP 668 環境限制。

mkdir -p ~/vllm-models
cd ~/vllm-models
pip install --user --break-system-packages -U "huggingface_hub[cli]"
export PATH="$HOME/.local/bin:$PATH"
hf download bg-digitalservices/Gemma-4-26B-A4B-it-NVFP4 \
  --local-dir Gemma-4-26B-A4B-it-NVFP4

步驟三：拉取映像檔與產生 Patch

修復 vLLM 讀取 NVFP4 專家層權重的 KeyError 問題 (vLLM Issue #38912)。

docker pull vllm/vllm-openai:gemma4-cu130
mkdir -p ~/vllm-patches
docker run --rm vllm/vllm-openai:gemma4-cu130 \
  cat /usr/local/lib/python3.12/dist-packages/vllm/model_executor/models/gemma4.py \
  > ~/vllm-patches/gemma4_patched.py
sed -i 's/param = params_dict\[name\]/param = params_dict.get(name, None)\n            if param is None: continue/g' \
  ~/vllm-patches/gemma4_patched.py

步驟四：Compose 配置與啟動

於 ~/vllm-compose/docker-compose.yml 配置卷冊與監聽埠，記憶體利用率設為 0.35。

# docker-compose.yml 關鍵配置：
# volumes:
#   - ${HOME}/vllm-models/Gemma-4-26B-A4B-it-NVFP4:/model
#   - ${HOME}/vllm-patches/gemma4_patched.py:/usr/local/.../gemma4.py:ro
# command:
#   - /model
#   - --served-model-name
#   - gemma-4-26b-a4b
#   - --host
#   - "0.0.0.0"
#   - --port
#   - "8002"
#   - --gpu-memory-utilization
#   - "0.35"

cd ~/vllm-compose
docker compose up -d

全端整合樞紐

提供與現有業務系統對接的程式範例。包含相容於 PHP 7.x 的 cURL 呼叫段落，以及 Antigravity IDE 的模型對接配置。

相容於 PHP 7.x 語法，透過 cURL 呼叫 vLLM OpenAI 相容端點進行地政案件號碼解析。

<?php
$dgx_ip = '192.168.13.195'; 
$apiUrl = "http://{$dgx_ip}:8002/v1/chat/completions";

$payload = [
    'model' => 'gemma-4-26b-a4b',
    'messages' => [
        ['role' => 'system', 'content' => '你是一位地政案件解析助手。'],
        ['role' => 'user', 'content' => '請查115年桃資速1200號']
    ],
    'temperature' => 0.1
];

$ch = curl_init($apiUrl);
curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);
curl_setopt($ch, CURLOPT_POST, true);
curl_setopt($ch, CURLOPT_POSTFIELDS, json_encode($payload));
curl_setopt($ch, CURLOPT_HTTPHEADER, ['Content-Type: application/json']);
curl_setopt($ch, CURLOPT_TIMEOUT, 30);

$response = curl_exec($ch);
curl_close($ch);

$result = json_decode($response, true);
echo $result['choices'][0]['message']['content'];
?>

常見障礙排除 (Troubleshooting)

點擊常見錯誤徵兆，檢視 Root Cause 與最小修補方案。

原因： 背景有 Ollama 佔用，或 --gpu-memory-utilization 設太高 (如 0.60)。
解法： 執行 sudo systemctl stop ollama 與刪除舊容器。將利用率參數調降為 0.35 (約 42GB)。
原因： vLLM NVFP4 解析迴圈缺陷，找不到被 ModelOpt 轉置的專家權重。
解法： 確保 gemma4_patched.py 成功以唯讀 :ro 權限掛載至容器內覆蓋預設腳本。
原因： vLLM 預設監聽 8000 Port，但 docker 映射了 8002，導致封包無法送達。
解法： 必須在 docker run 的 command 中明確加入 --host 0.0.0.0 與 --port 8002。
原因： 舊容器設定了 --restart always，單純 stop 無效。
解法： 執行 docker rm -f vllm-gemma-4 強制徹底刪除。
