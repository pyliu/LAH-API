1. 使用技術 Stack (Technology Stack)

🐍

Python 3.10+ Core Engine

主控語言環境，提供豐富的標準函式庫與跨平台動態執行能力，支援智慧編碼重構與流式 I/O。

🌐

Requests & urllib Web Scraping

負責 HTTP/HTTPS 請求處理，具備 Headers 輪換偽裝、網路 Session 逾時自動重試與 URL 相對路徑補齊。

🥣

BeautifulSoup4 DOM Parser

精準解析 HTML DOM 結構，自動抽取小說目錄連結、正文段落，過濾無關廣告標籤與 script 雜訊。

📄

ReportLab PDF Layout Engine

採用商業級 PDF 模板渲染器 (`BaseDocTemplate`, `PageTemplate`, `Frame`, `TableOfContents`)，實現動態 TOC 目錄與 PDF 書籤大綱。

🔤

corrections.py NLP Engine

自訂修仙專有名詞與台灣繁體習慣用語替換字典，包含動態 Regex 替換演算法，精準修正小說錯字。

💾

JSON State Database Persistence

使用輕量級 JSON 狀態檔（如 `progress_人靈界篇.json`）進行斷點續傳快取，確保意外中斷時無縫續接。

🐘

PHP 5+ Backend API Server

輕量級的儲存中介層，搭配 .env 處理 PIN 碼驗證，安全地將前端修改的錯字回寫至伺服器文字檔中。

🟢

Vue 3 + Tailwind CSS Frontend UI

以純前端框架打造流暢的跨裝置閱讀與即時編輯體驗，並已全面離線化所有依賴資源。

User Manual

2. 操作說明 (Usage & Operator Guide)

1

準備環境與字型驗證

確定系統已安裝 Python 3.8 或以上版本。Windows 系統預設已內建標楷體 (`C:/Windows/Fonts/kaiu.ttf`)。若為 Linux/macOS，請確認系統已有 Traditional Chinese 字型並修改路徑。

python --version
2

安裝依賴套件 (Dependencies)

開啟終端機執行 pip 命令，一次安裝爬蟲與 PDF 生成所需的套件：

pip install requests beautifulsoup4 reportlab
3

執行主要爬蟲與 PDF 匯出任務

執行 `build_catalog.py` 開始抓取《凡人修仙傳》人靈界篇。程式會自動建立 `output/人靈界篇/` 資料夾，下載正文並動態生成包含目錄的 PDF 批次檔。

python build_catalog.py
4

補充篇章與離線文字檔處理（選用）

若需抓取特定的外傳感言，可執行 `build_extra_pdf.py`；若已有本地文字檔（例如 `assets/本文/仙界篇/`），可執行 `make_batch001.py` 進行手動打包。

python build_extra_pdf.py # 下載外傳篇章 python make_batch001.py # 將本地 1~55 TXT 轉為 Batch 001 PDF
5

上傳至 Gemini Notebook 進行 AI 閱讀與問答

開啟 Google Gemini Notebook 介面，將 `output/` 目錄下產出的分批 PDF 檔案拖拽上傳。由於每個 Batch 嚴格控制在 27 萬字與 270 頁以內，可 100% 成功解析且不會被告警退件！

3. 遇到的難題與技術解決方案 (Technical Challenges)

難題 1

Windows CLI UTF-8 / CP950 編碼崩潰 (UnicodeEncodeError)

[系統與 Terminal]
⚠️ 問題現象與原因
Windows 命令提示字元 (cmd) 預設為 CP950 編碼。當爬蟲在印出進度日誌或章節標題時（包含 Emoji 符號如 🚀、📥 或簡轉繁罕見字），會直接拋出 `UnicodeEncodeError: 'cp950' codec can't encode character` 導致腳本中斷。
✅ 解決方案與核心程式碼
在程式啟動極早期，檢測 `sys.stdout` 與 `sys.stderr` 的 encoding，若是 CP950，強制調用 `reconfigure(encoding="utf-8", errors="replace")` 重構標準輸出串流。
if sys.stdout.encoding.upper() not in ("UTF-8", "UTF8"): sys.stdout.reconfigure(encoding="utf-8", errors="replace")
難題 2

Gemini Notebook 嚴格容量限制與 PDF 排版頁數溢估問題

[演算法與分批]
⚠️ 問題現象與原因
Gemini Notebook 限制每個文件上限 50 萬字與 500 頁。若依常規 A4 每頁 600 字計算，未考慮段落縮排、空行、標題與目錄頁佔用，實際生成的 PDF 經常在第 450 章節時暴增至 520 頁，被 Gemini Notebook 拒絕上傳。
✅ 解決方案與核心程式碼
建立 54% 保守安全邊距策略：將上限設為 270,000 字 / 270 頁。並修正估算模型為 450 字/頁 (`CHARS_PER_PAGE_EST = 450`)，雙重閥值動態觸發新 Batch 生成，達成 100% 安全 Pass。
MAX_CHARS_PER_BATCH = 270_000 # 54% 安全邊距 MAX_PAGES_PER_BATCH = 270 # 54% 頁數邊距
難題 3

ReportLab 雙 Pass 動態目錄 (TOC) 與 PDF 導覽書籤同步

[PDF Layout 引擎]
⚠️ 問題現象與原因
ReportLab 在繪製 Table of Contents (TOC) 時，目錄位於文件開頭，但在渲染開頭時無法預知幾百章之後的章節會落在實體 PDF 的第幾頁。且標準模板不會自動在 PDF 左側邊欄建立可點擊的章節書籤。
✅ 解決方案與核心程式碼
繼承 `BaseDocTemplate` 實作自訂 `TocDocTemplate`。覆寫 `afterFlowable` 鉤子，在渲染章節標題時發送 `TOCEntry` 通知並呼叫 `self.canv.bookmarkPage(key)`，搭配 ReportLab 兩次渲染運算自動計算正確頁碼與書籤導覽。
難題 4

目標網站反爬蟲 (Anti-Scraping) 與長效下載中斷復原

[網路與持久化]
⚠️ 問題現象與原因
長達 2400 多章節的連鎖下載，若固定請求頻率容易觸發伺服器 HTTP 429 Rate Limit、503 Service Unavailable 或 IP 暫時封鎖。一旦網路發生閃斷，若無狀態記錄將導致整批作業重新開始。
✅ 解決方案與核心程式碼
(1) 建置 `USER_AGENTS` 陣列隨機輪換 Header。(2) 採用 `random.uniform(3.0, 8.0)` 浮動隨機延遲。(3) 實作 JSON 斷點續傳持久化，每成功抓取一章即時 append 寫入 `progress_*.json`。
難題 5

修仙小說專有名詞繁簡轉換與錯別字成詞校正

[NLP 語意處理]
⚠️ 問題現象與原因
一般的 OpenCC 或簡單繁簡轉換套件，常誤將修仙專有名詞轉錯（例如將「乾坤」轉為「干坤」、「符籙」轉為「符箓」）或無法辨識簡體小說網常見的掃描錯別字。
✅ 解決方案與核心程式碼
專為修仙題材開發 `corrections.py` 字典與 `apply_corrections(text)` 函式，建立優先級正則替換矩陣，精準修正台灣慣用語、特殊修仙功法名稱與標點符號排版。

5. 安裝建置流程 (Installation & Build Flow)

完整安裝建置步驟命令

1. 克隆專案或準備專案目錄：

cd c:\Temp\mortal_to_immortal_novel

2. 建立並啟用 Python 虛擬環境 (推薦)：

python -m venv venv # Windows 啟用 venv\Scripts\activate # Linux / macOS 啟用 source venv/bin/activate

3. 安裝核心依賴庫：

pip install --upgrade pip pip install requests beautifulsoup4 reportlab

4. 驗證字型檔 (`kaiu.ttf`)：

Windows 預設路徑為 `C:/Windows/Fonts/kaiu.ttf`。若於 Linux 或 macOS 執行，請將系統中文字型檔複製至專案目錄或修改 `build_catalog.py` 中 `FONT_PATH` 設定。

5. 啟動建置與 PDF 匯出驗證：

python build_catalog.py
